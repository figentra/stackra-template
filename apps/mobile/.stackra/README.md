# apps/mobile/.stackra (generated, gitignored; committed in this template only to be read)

Everything here is written by `stackra gen` from `stackra.config.ts` (S), `runway.yaml` (RM), the
root `runway.yaml` (RR), `src/config/*.config.ts` (C/<fact>), `mise.toml` (T), the kind classes
under `src/` (K: routes, the layout, menus, blocks, documents, the store, config classes, analytics
events, refusals, found by their group folders; ADR 0294) and the consumed services' committed
`stackra.manifest.json` (M; the remote modules `src/mobile.module.ts` imports). A real project
ignores `.stackra/` entirely and rebuilds it on `pnpm gen`, on save under `stackra dev`, and before
`build`, `test` and `typecheck`; the committed contract is `../stackra.manifest.json` at the member
root (ADR 0294 decision 10). Every file starts with
`generated by stackra gen from <sources> — do not edit`.

Expo CLI, EAS and Vitest read their config from the member ROOT, so gen also writes four thin root
shims, all gitignored (ADR 0295 decision 5): `app.config.ts`, `metro.config.js` and
`vitest.config.ts` (one-line re-exports of the files below) and `eas.json` (a copy, JSON cannot
re-export; `stackra build` and `stackra release` resolve its `ref:` values while copying).
`package.json` `main` points at `.stackra/entry/native.ts`, so no entry shim is needed. No Babel
config is written: no section adds a plugin, and Expo's default preset already enables legacy
decorators and the worklets plugin. No code hatch exists (`expo.extend.ts`, `metro.extend.ts`). EAS
reads only the repository-root `.easignore`, which gen also writes: it keeps this folder and the
shims in the upload although git ignores them.

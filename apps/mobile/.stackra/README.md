# apps/mobile/.stackra (generated; gitignored except `app-manifest.json`; committed in this template only to be read)

Everything here is written by `stackra gen` from `stackra.config.ts` (S), `runway.yaml` (RM), the
root `runway.yaml` (RR), `src/config/*.config.ts` (C/<fact>), `mise.toml` (T), the decorated classes
under `src/` (D: `@App`, `@Route`, `@Layout`, `@Provider`, `@Store`, `@Block`, `@Document`, `@Menu`,
`@Override`, `@Config`, `@AnalyticsEvent`) and the consumed services' committed manifests (M;
inferred from `#stackra/clients` imports). A real project ignores `.stackra/*` except the committed
`app-manifest.json`, and rebuilds the rest on `pnpm gen`, on save under `stackra dev`, and before
`build`, `test` and `typecheck`. Every file starts with
`generated by stackra gen from <sources> — do not edit`.

Expo CLI and EAS read their config from the member ROOT, so gen also writes three thin root shims,
all gitignored: `app.config.ts`, `metro.config.js` (one-line re-exports of the files below) and
`eas.json` (a copy, JSON cannot re-export; `stackra build` and `stackra release` resolve its `ref:`
values while copying). `package.json` `main` points at `.stackra/main.ts`, so no entry shim is
needed. No Babel config is written: Expo's default preset already enables legacy decorators and the
worklets plugin. EAS reads only the repository-root `.easignore`, which gen also writes: it keeps
this folder and the shims in the upload although git ignores them.

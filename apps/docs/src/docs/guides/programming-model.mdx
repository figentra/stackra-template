Boundary: a guide; its code is illustrative (an orders module in a service you add, services/<name>), since the lean starter's two examples are empty. > Actions are the only behaviour; everything else reaches, extends, schedules or reacts to one.

This project follows the Stackra programming model v3.1. It amends
[ADR 0294](https://docs.stackra.figentra.com/adr/0294-programming-model-v3-grammar-folders-identities-and-naming);
the amendments are
[ADR 0305](https://docs.stackra.figentra.com/adr/0305-programming-model-v3-1-names-partners-files-and-class-components)
(names, partners, files and class components) and ADR 0306 to 0309 (overrides, panel, integrations,
icons); the repository's `AGENTS.md` states the rules. The examples below are illustrative: they use
an `orders` module in a service you add (`services/<name>`); the starter's `services/example` and
`packages/application/example` are empty until you write the first module. Four sentences carry it:

1. **The path says the kind.** `orders/actions/cancel-order.action.ts` is an action of the `orders`
   module; nobody has to open the file to know it.
2. **The base class is the kind.**
   `class CancelOrderAction extends Action({ key: "order.cancel" })`. There are no kind decorators.
3. **The type gives the shape.** A field's TypeScript type is its rule, its column and its wire
   type; gen compiles shapes to Zod and models to MikroORM metadata.
4. **The names give identity.** You write each wire name once (an action key, an event name, a route
   path); every other identity is derived and locked in the member's committed
   `stackra.manifest.json`.

Why a base class rather than a decorator: the base class is where TypeScript checks the kind and its
options together, gen reads it from the syntax tree without running code, and nothing needs
`reflect-metadata`. Decorators remain for facts about one member: a field rule (`@Str`, `@Secret`),
a workflow step, a state transition, or a class facet such as `@Searchable`.

## Grammar

| Rule | What it says                                                                                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | A file is `<scope>/<group>/<name>.<kind>.ts(x)`; a route, block or component is a folder, `<group>/<name>/<name>.<kind>.ts(x)`. Each suffix has one home group. Tests sit in `__tests__/`.                              |
| R2   | Strictly one exported declaration per file. Input and Output are `schemas/<name>-input.schema.ts` and `-output.schema.ts`; Props are `<name>.props.ts`; a hook's result type is `types/<name>.type.ts`.                 |
| R3   | The base class is the kind; its options are the argument. Bare without options (`extends Schema`), called with them (`extends Refusal({ kind })`). Kind bases are `PascalCase(kind)`, never `define*`.                  |
| R4   | The type gives the shape: the initializer is the default, `?:` optional, `\| null` nullable, and a `number` carries `@Int` or `@Num`. A literal union or `any` fails gen.                                               |
| R5   | Names give identity, written once and locked; a rename carries `@Renamed(old)`.                                                                                                                                         |
| R6   | Decorators are field decorators (constraints, transforms, `@Classified`, relations, `@Secret("NAME")`, `@Setting`), `@Step` and `@Transition`, or class facets (`@Index`, `@Searchable`, `@AccessLogged`, `@Lifetime`). |
| R7   | Components are classes, `extends Component<Props>`, compiled by gen to function components; a `.mail.tsx` mail body is one too. React hooks, plain functions and server helpers stay functions.                         |
| R8   | A type an exported signature needs is its own `types/<name>.type.ts`; enums have their own file.                                                                                                                        |
| R9   | One blank line between class members; a base-factory argument of two or more properties goes one per line; a four-field header and a one-line TSDoc on every member.                                                    |
| R10  | `.stackra/` is generated and gitignored; the committed contracts are `stackra.manifest.json` and `openapi.json` at the member root.                                                                                     |
| R11  | A partner is a type argument (`Policy<Order>`, `Resource<Order>({…})`, `Widget<OrderKpisQuery>({…})`); a value argument only where members are inherited (`Driver(Port)`, `Widget.place(BaseX, {…})`, `extends BaseX`). |
| R12  | Every member authors `stackra.config.ts`; a `<key>.module.ts` exists only when it says something gen cannot derive. Nobody writes `main.ts`, an entry barrel or an `index.ts` beside a root module.                     |

## A feature, end to end

| Step                       | File in `services/<name>/src/modules/`                             | Form                                                                     |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| the permission             | `orders/access/order.permissions.ts`                               | `extends Permissions`, `static readonly cancel = Permission.L2`          |
| the record rule            | `orders/access/order.policy.ts`                                    | `extends Policy<Order>`, one method per verb                             |
| the event                  | `orders/events/order-paid.event.ts`                                | `extends IntegrationEvent({ name: "order.paid" })`                       |
| the wire shapes            | `orders/schemas/create-order-input.schema.ts`, `-output.schema.ts` | `extends Schema`, one class per file                                     |
| the action                 | `orders/actions/create-order.action.ts`                            | `extends Action({ key: "order.create", tool: true, intent: true })`      |
| the long work behind it    | `orders/workflows/create-order.workflow.ts`                        | `extends Workflow<CreateOrderInput>({ timeout })`, step methods          |
| the place others extend    | `orders/extensions/order.extension-point.ts`                       | `extends ExtensionPoint`, `before` and `after` slots                     |
| another module's extension | `loyalty/extensions/redeem-points.extension.ts`                    | `extends Extension<OrderExtensionPoint["adjustTotals"]>({ order: 200 })` |
| the reaction to an event   | `loyalty/listeners/earn-on-order-paid.listener.ts`                 | `extends Listener`, `handle(event: OrderPaid, ctx)`                      |
| the message to the buyer   | `orders/resources/order/order-receipt.notification.ts`             | `extends Notification({ category })`, `mail()` channel                   |
| the console screen         | `orders/resources/order/order.resource.ts`                         | `extends Resource<Order, OrderView>({ area, navigation, operations })`   |
| the dashboard numbers      | `orders/resources/order/order-kpis.widget.ts`                      | `extends Widget<OrderKpisQuery>({ slot: Slots.Dashboard.Header })`       |
| what gen derived           | `services/<name>/.stackra/gen/wiring.ts`, `stackra.manifest.json`  | generated, never edited                                                  |

```ts
// orders/actions/cancel-order.action.ts (abridged)
export class CancelOrderAction extends Action({
  key: "order.cancel",
  actors: [ActorKind.User, ActorKind.Agent, ActorKind.Service],
  tool: true,
}) {
  /** @param orders - reads and transitions the order. */
  constructor(private readonly orders: OrderService) {
    super();
  }

  /** Cancels an unpaid order after the record policy allows it. */
  async handle(input: CancelOrderInput, ctx: ActionContext): Promise<CancelOrderOutput> {
    const order = await this.orders.findOneOrFail({ id: input.orderId });
    await ctx.authorize(order);
    this.orders.cancel(order, CancelReason.Staff);
    return CancelOrderOutput.create({ orderId: order.id, status: order.status });
  }
}
```

From that one class gen derives the wire key `orders.order.cancel@1`, the permission
`orders.order.cancel` (its risk is the `Permission.L2` on `OrderPermissions.cancel`, so a person
confirms and an agent needs approval), the route `PUT /orders/:orderId/cancel`, the MCP tool
`orders_order_cancel`, and the input and output schemas from the types of `handle`, which live in
`orders/schemas/cancel-order-input.schema.ts` and `cancel-order-output.schema.ts`.

An action reaches its callers through four typed surfaces, each defaulted from the key and the
actors and locked in the manifest: `endpoint` (on when a user or an agent may call it), `tool` (on
for queries, opt-in for actions), `job` (a queue or a cron) and `intent` (the palette and agents
find it by phrases in the lang files, `orders::actions.order.create.intents`, in every locale).
Confirmation follows the permission level; there is no `ux` option.

## Group folders

A module is `src/modules/<key>/` in a service and `src/node/` in a package; a group folder appears
with its first file.

| Group                                | Holds                                                                                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| (module root)                        | `<key>.module.ts` (only for `exports`), `<key>.settings.ts`, `README.md`                                                       |
| `models/`                            | `.model.ts`, `.state-machine.ts`, `.bucket.ts`, `.projection.ts`                                                               |
| `actions/`, `queries/`               | `.action.ts`, `.query.ts`                                                                                                      |
| `schemas/`                           | `.schema.ts` (every Input, Output, Data, view and options shape), `.change.ts` (a dated response change)                       |
| `enums/`, `errors/`                  | `.enum.ts`, `.error.ts`                                                                                                        |
| `events/`                            | `.event.ts`, `.change.ts` (an event version beside its event)                                                                  |
| `listeners/`, `workflows/`           | `.listener.ts`; `.workflow.ts`, `.signal.ts`                                                                                   |
| `access/`                            | `.permissions.ts`, `.policy.ts`, `.role.ts`, `.entitlement.ts`, `.precondition.ts`, `.flag.ts`                                 |
| `services/`, `drivers/`              | `.service.ts`, `.repository.ts` (named reads beyond `CrudService` only); `.driver.ts`                                          |
| `integrations/`, `connections/`      | `.integration.ts`, `.connection.ts`                                                                                            |
| `extensions/`                        | `.extension-point.ts`, `.extension.ts`, `.interceptor.ts`                                                                      |
| `raw/`                               | `.controller.ts`, in a service only                                                                                            |
| `resources/<model>/`                 | `.resource.ts`, `.widget.ts`, `.document.ts`, `.notification.ts`, `.mail.tsx`                                                  |
| `database/`                          | `migrations/NNNN-<name>.migration.ts`, `macros/<name>.macro.ts`, `factories/<model>.factory.ts`, `seeders/<profile>.seeder.ts` |
| `ai/`                                | `.prompt.ts`, `.skill.ts`, `.facts.ts`                                                                                         |
| `functions/`, `constants/`, `types/` | `.function.ts`, `.constant.ts`, `.type.ts`                                                                                     |

Each module's tables live in a Postgres schema named after the module key (`orders.orders`,
`catalogue.products`) inside the service's one database, and its migrations are numbered from `0001`
and change only that schema.

An app's `src/` holds an optional root module, then `config/` (including `desktop.config.ts` and
`chrome.config.ts`), `panels/`, `menus/`, `shortcuts/`, `documents/`, `stores/`, `flags/`,
`analytics/` and `bridges/`, the folder kinds `routes/<name>/`, `blocks/<name>/` and
`components/<name>/` (each component with its `<name>.props.ts`), `hooks/` for a hook with two or
more importers, `overrides/<owner>/…`, `enums/`, `types/`, `styles/`, and `schemas/` and `errors/`
for its own shapes and refusals. A package's `src/` holds `contracts/` (the leaf: `ports/`,
`enums/`, `types/`), `config/`, `core/`, `node/` (its module), `react/<name>/`, `native/<name>/` and
`testing/` (`<name>.fake.ts`, `<name>.matcher.ts`, `<name>.fixture.ts`); its entry barrels are
generated.

## The kind table

| Kind                       | Declared as                                                                                                                                     |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Module, settings           | `Module({ exports, imports, wrap })` when it states one; `extends Settings({ scopes })`, sections as schema-typed fields                        |
| Model, state machine       | `extends Model.with(...traits)`; `extends StateMachine<Order>({ field })` with `@Transition` methods                                            |
| Schema, enum               | `extends Schema` or another schema class (`PickType`, `OmitType`, `PartialType`), `CursorInput` or `Page.of(X)`; `Enum.of({...})` with its type |
| Error                      | `extends Refusal({ kind })`, thrown as `X.create({...})`                                                                                        |
| Action, query              | `extends Action({ key, endpoint, tool, job, intent })`, `extends Query({ key, cache })`                                                         |
| Event, change              | from `@stackra/events`: `DomainEvent`, `IntegrationEvent({ name })`, `WebhookEvent<I>({ type })`, `AnalyticsEvent({ name })`; `Change<S>({…})`  |
| Listener, projection       | `extends Listener` or `Listener({ queue })`; `extends Projection<Source>({...})`                                                                |
| Workflow, signal           | `extends Workflow({ startOn, timeout })` or `Workflow<Input>({ timeout })`; `extends Signal`                                                    |
| Access                     | `extends Permissions`, `Policy<Order>`, `Role({ grants })`, `Precondition`, `Entitlement({...})`, `Flag({...})`                                 |
| Service, driver, port      | `extends CrudService<Order>` or `Service`; `extends Driver(Port)`; `abstract class X extends Port`                                              |
| Integration, connection    | `extends Integration({ provider, category, levels, auth, ... })`; `extends Connection<XIntegration>` with `@Secret` fields and `check()`        |
| Extension point, extension | `extends ExtensionPoint` (`before`, `after` slots); `extends Extension<Point["slot"]>({ order })` with one `handle`; `extends Interceptor`      |
| Interface kinds            | `Resource<Order>({...})` or `Resource<Order, OrderView>({...})`, `Widget<Query>({...})`, `Document({...})`, `Notification({ category })`        |
| Database kinds             | `extends Migration` or `Migration({ after })`, `extends Macro`, `extends Factory<Order>`, `extends Seeder`                                      |
| AI kinds                   | `extends Prompt` or `Prompt({...})`, `extends Skill({ tools })`, `extends Facts<Order>`                                                         |
| App kinds                  | `Route({ path })`, `Layout`, `Panel`, `Menu({ kind })`, `Shortcut({ keys })`, `Store`, `Block`, `Bridge`, `Component<Props>`                    |
| Config                     | `extends Config({ schema: XOptions, env: { field: "ENV" } })`; a host override `X extends BaseX` sets `override` defaults only                  |

A model never takes a kind base's name, so the inbox entry model is `InboxMessage`, not
`Notification`. A constructor parameter names its dependency by its type: classes are the only
tokens, and `@Lifetime` is the only scope marker. There is no `@Injectable`, `@Inject` or providers
array; gen writes the wiring.

## Class components

A component is a class, and gen compiles it to a plain function component before the React Compiler
runs (`classComponents()` from `@stackra/gen/node` in the generated Vite config,
`@stackra/gen/metro-transformer` in the generated Metro config):

```tsx
// illustrative: apps/<app>/src/routes/dashboard/dashboard.tsx (abridged)
export class Dashboard extends Component<RouteProps<typeof DashboardRoute>> {
  /** The translator of the active locale. */
  i18n = useTranslation();

  /** Today's KPIs, warm from the loader. */
  kpis = useQuery(OrderKpisQuery, { range: TimeRange.Today });

  /** The heading, the loading and error states, then the panel's grid. */
  render() {
    const { t } = this.i18n;
    return (
      <div className="flex flex-col gap-6">
        <h1 className="sr-only">{t(I18n.pages.dashboard.title)}</h1>
        {this.kpis.isPending && <LoadingState label={I18n.pages.dashboard.loading} rows={2} />}
        {this.kpis.error && (
          <ErrorState error={this.kpis.error} onRetry={() => this.kpis.refetch()} />
        )}
        <PanelDashboard panel={Panels.TenantAdmin} slots={[Slots.Dashboard.Main]} overridable />
      </div>
    );
  }
}
```

A field with an initializer is state, `x?: T` an empty state field, and a field whose initializer
calls a hook (`i18n = useTranslation()`, `inputRef = useRef<HTMLInputElement>(null)`) is a read-only
hook field. Methods are plain functions, getters are derived values, `mount()` and a synchronous
`unmount()` are the lifecycle, and `render()` may call hooks and return early. State is immutable:
assign a new value (`this.items = [...this.items, item]`), never mutate. A constructor, `static` or
`#private` members, setters, class decorators, `this.setState`, `this.state`, `this.context`, a bare
`this` and ref forwarding are gen errors. After `this.count++`, `this.count` still reads the
render's value in the same handler, so write the new value explicitly when you need it. A context is
read with a hook field or `use(Ctx)`; a provider is a component that renders `<Ctx value={…}>`.
`Component` comes from `#stackra/ui` (other components from `@stackra/ui/react` or
`@stackra/ui/native`), never from `react`, and an error boundary is never a class:
`@stackra/navigation` owns it.

## Derived identities

| Identity            | Formula                                                                   | Example                              |
| ------------------- | ------------------------------------------------------------------------- | ------------------------------------ |
| Member, module key  | the member's folder name; the module's folder name; both snake_case       | `example`, `orders`                  |
| Model key, table    | `<module>.<snake(Class)>`; the plural table in the module's schema        | `orders.order_line`, `orders.orders` |
| Permission          | `<module>.<snake(class minus "Permissions")>.<static>`                    | `orders.order.cancel`                |
| Action or query key | `<module>.` + `key` + `@<major>`                                          | `orders.order.cancel@1`              |
| MCP tool            | the key with dots as underscores                                          | `orders_order_cancel`                |
| Integration event   | `<module>.` + `name` + `.v<n>`                                            | `orders.order.paid.v1`               |
| Migration id        | `<module>.<NNNN>_<snake(stem)>`                                           | `orders.0002_add_order_paid_at`      |
| Error code          | `snake(class minus "Error")`                                              | `order_not_payable`                  |
| Config key          | the member key for the file named after it, else `<member>.<snake(stem)>` | `example.rate_limit`                 |
| i18n default keys   | `<module>::<kind>.<name>.<part>`                                          | `orders::enums.order_status.paid`    |

Endpoints follow the key the way Rails resource routing does: `order.list` is `GET /orders`,
`order.get` is `GET /orders/:orderId`, `order.create` is `POST /orders`, any other verb whose input
names `orderId` is `PUT /orders/:orderId/<verb>`, and any other query is `GET /orders/<name>`
(`order.kpis` is `GET /orders/kpis`). `endpoint: { method, path }` keeps a path the convention would
not give.

## Words that mean one thing

| Word                | Means only                                                                           | Not this                                                   |
| ------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| action, query       | a write; a read                                                                      | a route's `submit()`; a desktop bridge                     |
| command             | a CLI command                                                                        | a palette or key entry, which is a shortcut                |
| job                 | an action run from a queue or a cron (`job:` option)                                 | a kind of its own                                          |
| precondition        | whether a call may run now, whoever asks                                             | a guard (retired)                                          |
| policy              | record rules for one model, one method per verb                                      | a precondition                                             |
| extension point     | the seam a module owns and publishes, with `before` and `after` slots                | a backend hook (retired); a React hook                     |
| extension           | one class in another module that implements one slot                                 | a tool plugin                                              |
| interceptor         | the `around` of one action call                                                      | a method-level around (never)                              |
| override            | a file in `src/overrides/<owner>/…` that shadows the owner's file at the same path   | `.override.tsx` (retired); `@Replaces(Port)` for a binding |
| component, provider | a class compiled to a function component; a component that renders a context's value | React's `Component`; a DI binding                          |
| macro               | a named `Blueprint` helper a package or module owns (`t.belongsToTenant()`)          | a column list pasted into every migration                  |
| link                | a relation to another module's model, typed `Link<T>`                                | a `links/` folder (retired)                                |
| notification, toast | a message to people; a transient in-app message                                      | a mail class (retired)                                     |
| change              | a versioned conversion of an event or a response                                     | an `@Upcast` class (retired)                               |
| fixture             | a test helper value in a package's `testing/<name>.fixture.ts`                       | a `.factory.ts`, which is a `Factory<Model>` only          |
| service             | a deployable under `services/<name>`, or a `.service.ts` class                       | context makes it clear: a member or a module service       |

## Extending another module

An **extension point** is the seam the owning module publishes; an **extension** is one class in
another module that implements one of its slots. `before` runs ahead of the owner's step and may
refuse (throw a Refusal) or return replacement arguments; `after` receives the value the owner
computed and returns the adjusted one, each extension seeing the previous result. Wrapping a whole
action call, Magento's `around`, is an `Interceptor`.

```ts
// orders/extensions/order.extension-point.ts
export class OrderExtensionPoint extends ExtensionPoint {
  /** After pricing a draft; each extension returns the totals it adjusted. */
  readonly adjustTotals = ExtensionPoint.after<OrderTotals, [draft: OrderDraft]>();

  /** Before stock or payment is touched; an extension refuses by throwing a Refusal. */
  readonly verifyPlacement = ExtensionPoint.before<[draft: OrderDraft]>();
}

// loyalty/extensions/redeem-points.extension.ts: one slot, one `handle`
export class RedeemPointsExtension extends Extension<OrderExtensionPoint["adjustTotals"]>({
  order: 200,
  input: RedeemPointsRequest,
}) {
  /** Returns `totals` unchanged when no points were requested. */
  async handle(
    totals: OrderTotals,
    draft: OrderDraft,
    ctx: ExtensionContext,
  ): Promise<OrderTotals> {
    // …
  }
}
```

The other ways to change what you do not own: place a widget with `Widget.place(BaseX, {…})`, shadow
a file in `src/overrides/<owner>/…` (the owner is the package name with its scope, or
`<service>/<module>`), override a config in `src/config/`, or replace a binding with
`@Replaces(Port)`. A shadow keeps its base's name and imports the base under a `Base` alias
(`import { PointsBalanceWidget as BasePointsBalanceWidget } from "@figentra/acme-example/node"`).

## Links point down

A route names its layout by class and is the only file that imports a route class's neighbours:

```ts
// illustrative: apps/<app>/src/routes/dashboard/dashboard.route.ts (abridged)
export class DashboardRoute extends Route({
  path: "/",
  layout: ShellLayout,
  tab: {
    order: 1,
    icon: "house",
  },
}) {}
```

Its page is `dashboard.tsx` in the same folder, bound by name. A layout, menu, page or document
refers to a route by its generated key, `Routes.dashboard` from `#stackra/routes`:
`navigate.to(Routes.dashboard)`, `ctx.redirect(Routes.sign_in)`, `m.route(Routes.store)`. A layout
has no tab list: each tab route declares `tab`, and one optional `menus/tab-bar.menu.ts` rearranges
the bar. Icons are `IconName` strings (Lucide names in kebab-case), never imported components.

## Reaching a sibling module

Inside one member, a module imports a sibling only through the classes the sibling's
`Module({ exports })` lists and its public groups: `schemas/`, `enums/`, `events/`, `errors/`,
`access/*.permissions.ts` and `extensions/*.extension-point.ts`. A sibling's `models/` are imported
only from `models/` and `database/`, for relations and factories. A test under `__tests__/` may also
import a sibling's `database/factories/` and `models/` to arrange its data (an orders test seeds a
catalogue variant with `VariantFactory`).

## Reaching another service

Three ways, one per question: `client.x.y(input)` when you need the answer now;
`client.x.y.queue(input)` when it must happen but you do not need the answer; a listener whose
`handle` takes the producer's event class (`event: PaymentCaptured`, imported from
`#stackra/clients/payments`) when something happened. The client is generated from the producer's
committed `stackra.manifest.json`; the root runway's topology decides whether it runs in the same
process or over RPC, and the calling code never changes. You never import another service's code,
tables or package.

## Config and where a fact goes

Behaviour is a config class in `src/config/` whose options are a shape class, much like NestJS's
`registerAs` with a validation schema:

```ts
// illustrative: services/<name>/src/config/orders.config.ts
export class OrdersConfig extends Config({
  schema: OrdersOptions,
  env: { storefrontBaseUrl: "STACKRA_STOREFRONT_BASE_URL" },
}) {}
```

`OrdersOptions` is `schemas/orders-options.schema.ts`: fields, types, defaults, field decorators,
and `@Secret("PRICING_API_KEY")` on a secret field. `env` maps a field to its environment variable.
The class is the DI token and its key is derived; two classes deriving one key, or a second override
of one base, fail gen, so there is no "last one wins". A host changes a package's behaviour with an
override that keeps the base's name:
`class ExampleConfig extends BaseExampleConfig { override pageSize = 50; }`. It is read through the
container, by constructor injection in a binding or `useConfig(Class)` in a component. An override
carries no `env`: an app keeps every public environment value in its one `EnvConfig`
(`src/schemas/env-options.schema.ts`), and a field named after a package config field feeds it
(`identityIssuer` feeds `identity.issuer`).

| The fact is                                                | It goes in                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| the same everywhere and read only by build tools           | `stackra.config.ts` (`defineApp`, `defineService`, `definePackage`) |
| read by code while the app runs                            | a config class in `src/config/` and its options schema              |
| changed by a tenant admin at run time                      | the module's settings                                               |
| different per environment (sizes, values, dedicated needs) | the member's `runway.yaml`                                          |
| where members run and how they are packed                  | the root `runway.yaml` topology                                     |
| derivable from other facts                                 | nowhere: gen writes it                                              |

A cached read is the query's `cache: { ttl, invalidateOn }`; a cached value inside a service is the
injected `Cache` port with `CacheKey.of(Model, …)`. There is no `@Cached` and no cache module to
import.

## Migrations

`stackra db diff` writes the next migration from the models. A migration is a frozen snapshot: it
imports only `@stackra/database` and `#stackra/migrations`, names tables and columns with literals,
and calls macros for Stackra's column conventions (`t.hasPublicId("ord")`, `t.belongsToTenant()`,
`t.money("total")`, `t.timestamps()`). You write `up()` only; gen derives the inverse for local,
preview and test databases, `schema.sql(statement, { inverse })` is the one hand-written inverse
(`inverse: false` marks a step rollback stops at), and production is forward-only.
`Migration({ after: [Migrations.<module>.<stem>] })` orders a migration after another member's. Gen
classes every operation (additive, online, contract, banned) and refuses an unsafe one, such as an
index on an existing table without `.concurrently()`.

## Clients and sites

The lean starter has no app; a product adds one (a console, a mobile app or a public site) when it
needs it. Every app consumes manifests the same way: it imports a service's classes by name from
`#stackra/clients/<service>` (`CreateOrderAction`, `GetOrderQuery`, `OrderPaid`), gen infers the
consumed services from those imports and records them in the app's manifest. Types come from the
class, `ActionInput<typeof CreateOrderAction>`, never from a hand-written type. Routes are keyed by
their snake_case route key in `#stackra/routes`. A public site is restricted to the `public` API
area; a reference to anything else is a gen error. Its route modules never import server-only code:
the public clients and the server env reach every loader through the Worker's load context, and a
GET for HTML never sets a cookie.

Strings live in `assets/lang/<locale>/<namespace>.json`; `en` and `ar` are the base locales, and the
regional overlays `en-US` and `ar-SA` (`Locale.EnUs`, `Locale.ArSa`) hold only the keys that differ.
`@stackra/i18n` resolves the fallback, `src/config/i18n.config.ts` lists the locales and the URL
strategy, and gen merges and checks the files.

Ready to change something? Rename `services/example` to your first service, or write a new one with
`stackra new service <name> --area app`, then add its first module; the [testing](/guides/testing)
guide says where each test goes.

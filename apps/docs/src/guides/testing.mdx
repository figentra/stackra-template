Every test file sits in a `__tests__/` folder beside its subject and is named after it
(`access/order.policy.ts` → `access/__tests__/order.policy.test.ts`). Every `describe` names its
subject by class, and every `describe` and `it` carries a docblock saying why the case matters. The
tier is in the file name: unit is unmarked, `.int.test.ts` uses a Postgres container,
`.contract.test.ts` checks the manifest against the previous release, `.e2e.test.ts` is Playwright,
and a mobile journey is a Maestro `*.flow.yaml` beside the routes it drives.

## Where helpers come from

`@stackra/testing` is the runner (vitest re-exported; never import `vitest` directly) plus the
generic tools. Everything domain-specific comes from the `./testing` entry of the package that owns
the concept:

| Need                                                                          | Import                                                                                             |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `describe`, `it`, `expect`, `vi`, `createMatcher`, `freezeClock`, `freezeIds` | `@stackra/testing`                                                                                 |
| render a component or a route (`render`, `renderRoute`, `axe`)                | `@stackra/testing/react`, `@stackra/testing/native`                                                |
| a container with memory drivers                                               | `createTestingModule(Root).useDrivers("memory")` from `@stackra/container/testing`                 |
| run an action or a query                                                      | `run`, `fakeActionContext` from `@stackra/actions/testing`                                         |
| actors with permissions                                                       | `actors` from `@stackra/iam/testing`                                                               |
| refusals                                                                      | `refusal`, `toRefuseWith` from `@stackra/errors/testing`                                           |
| events and the outbox                                                         | `toEmit`, `drainOutbox` from `@stackra/events/testing`                                             |
| a real database; model factories                                              | `usePostgres`, `Factory` from `@stackra/database/testing`                                          |
| notifications and mail bodies                                                 | `MemoryNotifier`, `renderMail` from `@stackra/notifications/testing`                               |
| another service or an app's client                                            | `fakeClient` from `@stackra/clients/testing`                                                       |
| settings and flags                                                            | `fakeSettings` from `@stackra/settings/testing`, `fakeFlags` from `@stackra/feature-flags/testing` |
| manifests                                                                     | `toMatchManifest`, `expectBackwardCompatible` from `@stackra/gen/testing`                          |

## One shape for faking a client

Apps and services fake a generated client the same way: by its typed path, never by a string or a
computed key.

```ts
const commerce = fakeClient(Commerce, (fake) => fake.queries.GetOrder.returns(order));
const pricing = fakeClient(PricingClient, (fake) =>
  fake.price.quote.throws(refusal(Refusals.pricing.no_price)),
);

expect(commerce.called(Commerce.queries.GetOrder)).toEqual([{ orderId: order.id }]);
const result = await run(CancelOrderAction, { orderId }, { as: actors.customer() });
expect(result).toRefuseWith(refusal(Refusals.orders.order_not_payable));
```

`Refusals` comes from `#stackra/manifest`, so a refusal reference is a generated constant. Errors in
tests are typed too: throw a declared refusal (`OrdersPausedError.create()`); `throw new Error` is
banned in tests as everywhere else. Ids come from factories (`OrderFactory.new().create()`, or
`.count(2).create()` for two), never from hand-typed strings such as `"ord_demo_1"`. A factory needs
no entity manager: the testing module the test compiled provides it.

## Budgets are tests

Axe runs in every end-to-end journey and fails on serious or critical findings; mobile pages run
`axe` and an RTL check under the Arabic locale in their unit tests. The site's `lighthouserc.yaml`
fails the build when a route exceeds its performance numbers, and every Arabic plural must carry all
six CLDR categories or gen fails.

`pnpm new <kind> <name>` writes the subject and its test together. The root `README.md` maps every
file kind to the test the scaffold writes with it.

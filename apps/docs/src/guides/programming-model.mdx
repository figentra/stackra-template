> Actions are the only behaviour; everything else reaches, extends, schedules or reacts to one.

This project follows the Stackra programming model v3
([ADR 0294](https://docs.stackra.figentra.com/adr/0294-programming-model-v3-grammar-folders-identities-and-naming)).
Four sentences carry it:

1. **The path says the kind.** `orders/actions/cancel-order.action.ts` is an action of the `orders`
   module; nobody has to open the file to know it.
2. **The base class is the kind.**
   `class CancelOrderAction extends Action({ key: "order.cancel" })`. There are no kind decorators.
3. **The type gives the shape.** A field's TypeScript type is its rule, its column and its wire
   type; gen compiles shapes to Zod and models to MikroORM metadata.
4. **The names give identity.** You write each wire name once (an action key, an event name, a route
   path); every other identity is derived and locked in the member's committed
   `stackra.manifest.json`.

## Grammar

| Rule | What it says                                                                                                                                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | A file is `<scope>/<group>/<name>.<kind>.ts(x)`; a route, block or component is a folder, `<group>/<name>/<name>.<kind>.ts(x)`. Each suffix has one home group. Tests sit in `__tests__/`.                                                  |
| R2   | One primary export per file, named from the file. Noun kinds (model, schema, enum, event, signal, analytics event, type) take no suffix; errors end in `Error`.                                                                             |
| R3   | The base class is the kind; its options are the argument. A member that replaces a base default carries `override`.                                                                                                                         |
| R4   | The type gives the shape: the initializer is the default, `?:` optional, `\| null` nullable, and a `number` carries `@Int` or `@Num`. A literal union or `any` fails gen.                                                                   |
| R5   | Names give identity, written once and locked; a rename carries `@Renamed(old)`.                                                                                                                                                             |
| R6   | Decorators are field decorators (constraints, transforms, serializers and `@Classified`, relations, sources such as `@Secret("NAME")`), `@Step` and `@Transition`, or class facets (`@Index`, `@Searchable`, `@AccessLogged`, `@Lifetime`). |
| R7   | Components, React hooks, plain functions, server helpers and mail bodies are functions, never classes.                                                                                                                                      |
| R8   | A type that serves one declaration stays in its file; a second importer moves it to `types/`.                                                                                                                                               |
| R9   | One blank line between class members; a base-factory argument of two or more properties goes one per line; a four-field header and a one-line TSDoc on every member.                                                                        |
| R10  | `.stackra/` is generated and gitignored; the committed contracts are `stackra.manifest.json` and `openapi.json` at the member root.                                                                                                         |
| R11  | A model inside a decorator is a thunk (`@ManyToOne(() => Variant)`). Same module: `Ref<T>` or `Collection<T>`. Another module: `Link<T>`, an indexed id with no foreign key.                                                                |
| R12  | Every member authors `stackra.config.ts` and one root module; nobody writes `main.ts` or an entry barrel. The docs app and the tooling presets are exempt.                                                                                  |

## A feature, end to end

| Step                       | File in `services/commerce/src/modules/`                            | Form                                                            |
| -------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------- |
| the permission             | `orders/access/order.permissions.ts`                                | `extends Permissions`, `static readonly cancel = Permission.L2` |
| the record rule            | `orders/access/order.policy.ts`                                     | `extends Policy(OrderPermissions)`, one method per verb         |
| the event                  | `orders/events/order-paid.event.ts`                                 | `extends IntegrationEvent({ name: "order.paid" })`              |
| the action                 | `orders/actions/create-order.action.ts`                             | `extends Action({ key: "order.create" })`                       |
| the long work behind it    | `orders/workflows/create-order.workflow.ts`                         | `extends Workflow<CreateOrderInput>({ timeout })`, step methods |
| the place others extend    | `orders/extensions/order.extension-point.ts`                        | `extends ExtensionPoint`, `transform` and `verify` properties   |
| another module's extension | `loyalty/extensions/redeem-points.extension.ts`                     | `extends Extension(OrderExtensionPoint, { order: 200 })`        |
| the reaction to an event   | `loyalty/listeners/earn-on-order-paid.listener.ts`                  | `extends Listener`, `handle(event: OrderPaid, ctx)`             |
| the message to the buyer   | `orders/resources/order/order-receipt.notification.ts`              | `extends Notification({ category })`, `mail()` channel          |
| the console screen         | `orders/resources/order/order.resource.ts`                          | `extends Resource(Order, { area, navigation, operations })`     |
| what gen derived           | `services/commerce/.stackra/gen/wiring.ts`, `stackra.manifest.json` | generated, never edited                                         |

```ts
// orders/actions/cancel-order.action.ts (abridged)
export class CancelOrderAction extends Action({
  key: "order.cancel",
  actors: [ActorKind.User, ActorKind.Agent, ActorKind.Service],
  tool: true,
  ux: {
    confirm: Tone.Danger,
    after: [UxAfter.Refresh],
  },
}) {
  /** @param orders - reads and transitions the order. */
  constructor(private readonly orders: OrderService) {
    super();
  }

  /** Cancels an unpaid order after the record policy allows it. */
  async handle(input: CancelOrderInput, ctx: ActionContext): Promise<CancelOrderOutput> {
    const order = await this.orders.findOneOrFail({ id: input.orderId });
    await ctx.authorize(order);
    this.orders.cancel(order, CancelReason.Staff);
    return CancelOrderOutput.create({ orderId: order.id, status: order.status });
  }
}
```

From that one class gen derives the wire key `orders.order.cancel@1`, the permission
`orders.order.cancel` (its risk is the `Permission.L2` on `OrderPermissions.cancel`), the route
`PUT /orders/:orderId/cancel`, the MCP tool, the confirmation text key
`orders::actions.order.cancel.confirm`, and the input and output schemas from the types of `handle`.
Closed sets are `Enum.of` values from the package that owns the option (`ActorKind.User`,
`UxAfter.Refresh`, `ErrorKind.Conflict`); a driver choice is a config field typed
`DriverName<Port>`.

## Group folders

A module is `src/modules/<key>/` in a service and `src/node/` in a package; a group folder appears
with its first file.

| Group                                | Holds                                                                                                |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| (module root)                        | `<key>.module.ts`, `<key>.settings.ts`, `README.md`                                                  |
| `models/`                            | `.model.ts`, `.state-machine.ts`, `.bucket.ts`, `.projection.ts`                                     |
| `actions/`, `queries/`               | `.action.ts`, `.query.ts`                                                                            |
| `schemas/`                           | `.schema.ts` (a shape two or more files use), `.change.ts` (a dated response change)                 |
| `enums/`, `errors/`                  | `.enum.ts`, `.error.ts`                                                                              |
| `events/`                            | `.event.ts`, `.change.ts` (an event version beside its event)                                        |
| `listeners/`, `workflows/`           | `.listener.ts`; `.workflow.ts`, `.signal.ts`                                                         |
| `access/`                            | `.permissions.ts`, `.policy.ts`, `.role.ts`, `.entitlement.ts`, `.precondition.ts`, `.flag.ts`       |
| `services/`, `drivers/`              | `.service.ts`, `.repository.ts` (named reads beyond `CrudService` only); `.driver.ts`                |
| `integrations/`, `connections/`      | `.integration.ts`, `.connection.ts`                                                                  |
| `extensions/`                        | `.extension-point.ts`, `.extension.ts`, `.interceptor.ts`                                            |
| `raw/`                               | `.controller.ts`, in a service only                                                                  |
| `resources/<model>/`                 | `.resource.ts`, `.widget.ts`, `.document.ts`, `.notification.ts`, `.mail.tsx`                        |
| `database/`                          | `migrations/NNNN-<name>.migration.ts`, `factories/<model>.factory.ts`, `seeders/<profile>.seeder.ts` |
| `ai/`                                | `.prompt.ts`, `.skill.ts`, `.facts.ts`                                                               |
| `functions/`, `constants/`, `types/` | `.function.ts`, `.constant.ts`, `.type.ts`                                                           |

Each module's tables live in a Postgres schema named after the module key (`orders.orders`,
`catalogue.products`) inside the service's one database, and its migrations are numbered from `0001`
and change only that schema.

An app's `src/` holds its root module and `app.error.tsx`, then `config/` (including
`desktop.config.ts` and `chrome.config.ts`), `panels/`, `menus/`, `shortcuts/`, `documents/`,
`stores/`, `flags/`, `analytics/` and `bridges/`, the folder kinds `routes/<name>/`,
`blocks/<name>/` and `components/<name>/`, `hooks/` for a hook with two or more importers,
`overrides/<owner>/`, `enums/`, `types/`, `styles/`, and `schemas/` and `errors/` for its own shapes
(form inputs, nested config objects, bridge inputs) and refusals. A package's `src/` holds
`contracts/` (the leaf: `ports/`, `enums/`, `types/`), `config/`, `core/`, `node/` (its module),
`react/<name>/`, `native/<name>/` and `testing/` (`<name>.fake.ts`, `<name>.matcher.ts`,
`<name>.fixture.ts`); its entry barrels are generated.

## The kind table

| Kind                       | Declared as                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Module, settings           | `extends Module` or `Module({ exports, imports, wrap })`; `extends Settings({ scopes })`                                                                                  |
| Model, state machine       | `extends Model.with(...traits)`; `extends StateMachine(Model, { field })` with `@Transition` methods                                                                      |
| Schema, enum               | `extends Schema` or another schema class (`PickType`, `OmitType`, `PartialType` derive one), `CursorInput` or `Page.of(X)`; `Enum.of({...})` with a type of the same name |
| Error                      | `extends Refusal({ kind })`, thrown as `X.create({...})`                                                                                                                  |
| Action, query              | `extends Action({ key, ... })`, `extends Query({ key, ... })`                                                                                                             |
| Event, change              | `extends DomainEvent`, `IntegrationEvent({ name, broadcast: { permission, audience } })`, `WebhookEvent({ path, scheme, secret })`; `extends Change(Subject, {...})`      |
| Listener, projection       | `extends Listener` or `Listener({ queue })`; `extends Projection(Source, {...})`                                                                                          |
| Workflow, signal           | `extends Workflow({ startOn, timeout })` or `Workflow<Input>({ timeout })`; `extends Signal`                                                                              |
| Access                     | `extends Permissions`, `Policy(XPermissions)`, `Role({ grants })`, `Precondition`, `Entitlement({...})`, `Flag({...})`                                                    |
| Service, driver, port      | `extends CrudService(Model)` or `Service`; `extends Driver(Port)`; `abstract class X extends Port`                                                                        |
| Integration, connection    | `extends Integration({ provider })`; `extends Connection(XIntegration, {...})` with `@Secret("NAME")` credential fields                                                   |
| Extension point, extension | `extends ExtensionPoint`; `extends Extension(Point, { order })`; `extends Interceptor`                                                                                    |
| Interface kinds            | `extends Resource(Model, {...})`, `Widget({...})` (`refreshOn` takes integration events only), `Document({...})`, `Notification({ category })`                            |
| Database kinds             | `extends Migration`, `extends Factory(Model)`, `extends Seeder`                                                                                                           |
| AI kinds                   | `extends Prompt` or `Prompt({...})`, `extends Skill({ tools })`, `extends Facts(Model)`                                                                                   |
| App kinds                  | `extends Route({ path })`, `Layout`, `Panel`, `Menu({ kind })`, `Shortcut({ keys })`, `Store`, `Block`, `Bridge`, `AnalyticsEvent({ name })`                              |
| Config                     | `extends Config` (the env contract is `<App>EnvConfig` in `env.config.ts`), or a host override `<Host><Base> extends Base` with `override` members only                   |

A model never takes a kind base's name, so the inbox entry model is `InboxMessage`, not
`Notification`. A broadcast names its permission and its audience: the principal (the default, for
an event about one person) or the tenant. A constructor parameter names its dependency by its type:
classes are the only tokens, and `@Lifetime` is the only scope marker. There is no `@Injectable`,
`@Inject` or providers array; gen writes the wiring.

## Derived identities

| Identity            | Formula                                                                   | Example                              |
| ------------------- | ------------------------------------------------------------------------- | ------------------------------------ |
| Member, module key  | the member's folder name; the module's folder name; both snake_case       | `commerce`, `orders`                 |
| Model key, table    | `<module>.<snake(Class)>`; the plural table in the module's schema        | `orders.order_line`, `orders.orders` |
| Permission          | `<module>.<snake(class minus "Permissions")>.<static>`                    | `orders.order.cancel`                |
| Action or query key | `<module>.` + `key` + `@<major>`                                          | `orders.order.cancel@1`              |
| Integration event   | `<module>.` + `name` + `.v<n>`                                            | `orders.order.paid.v1`               |
| Error code          | `snake(class minus "Error")`                                              | `order_not_payable`                  |
| Config key          | the member key for the file named after it, else `<member>.<snake(stem)>` | `commerce.rate_limit`                |
| i18n default keys   | `<module>::<kind>.<name>.<part>`                                          | `orders::enums.order_status.paid`    |

Endpoints follow the key the way Rails resource routing does: `order.list` is `GET /orders`,
`order.get` is `GET /orders/:orderId`, `order.create` is `POST /orders`, and any other verb whose
input names `orderId` is `PUT /orders/:orderId/<verb>`. `endpoint: { method, path }` keeps a path
the convention would not give (`GET /orders/stats/today`).

## Words that mean one thing

| Word                       | Means only                                                      | Not this                                                     |
| -------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------ |
| action, query              | a write; a read                                                 | a route's `submit()`; a desktop bridge                       |
| command                    | a CLI command                                                   | a palette or key entry, which is a shortcut                  |
| job                        | an action run from a queue or a cron (`job:` option)            | a kind of its own                                            |
| precondition               | whether a call may run now, whoever asks                        | a guard (retired)                                            |
| policy                     | record rules for one model, one method per verb                 | a precondition                                               |
| extension point, extension | a typed place to transform or refuse a value; one implementer   | a backend hook (retired); a React hook                       |
| override                   | a block or Custom widget renderer, or an asset, swapped by path | an override point (retired); `@Replaces(Port)` for a binding |
| provider                   | a React context component                                       | a DI binding                                                 |
| link                       | a relation to another module's model, typed `Link<T>`           | a `links/` folder (retired)                                  |
| notification, toast        | a message to people; a transient in-app message                 | a mail class (retired)                                       |
| change                     | a versioned conversion of an event or a response                | an `@Upcast` class (retired)                                 |
| fixture                    | a test helper value in a package's `testing/<name>.fixture.ts`  | a `.factory.ts`, which is a `Factory(Model)` only            |
| service                    | a deployable under `services/<name>`, or a `.service.ts` class  | context makes it clear: a member or a module service         |

## Links point down

A route names its layout by class and is the only file that imports a route class's neighbours:

```ts
// apps/console/src/routes/dashboard/dashboard.route.ts (abridged)
export class DashboardRoute extends Route({
  path: "/",
  layout: ShellLayout,
  tab: {
    order: 1,
    icon: Icons.House,
  },
}) {}
```

Its page is `dashboard.tsx` in the same folder, bound by name. A layout, menu, page or document
refers to a route by its generated key, `Routes.dashboard` from `#stackra/routes`:
`navigate.to(Routes.dashboard)`, `ctx.redirect(Routes.sign_in)`, `m.route(Routes.store)`. A layout
has no tab list: each tab route declares `tab`, and one optional `menus/tab-bar.menu.ts` rearranges
the bar. Only gen's route tree imports the route classes, so no import cycle can form.

## Reaching a sibling module

Inside one member, a module imports a sibling only through the classes the sibling's
`Module({ exports })` lists and its public groups: `schemas/`, `enums/`, `events/`, `errors/`,
`access/*.permissions.ts` and `extensions/*.extension-point.ts`. A sibling's `models/` are imported
only from `models/` and `database/`, for relations. A test under `__tests__/` may also import a
sibling's `database/factories/` and `models/` to arrange its data (an orders test seeds a catalogue
variant with `VariantFactory`).

## Reaching another service

Three ways, one per question: `client.x.y(input)` when you need the answer now;
`client.x.y.queue(input)` when it must happen but you do not need the answer; a listener whose
`handle` takes the producer's event class (`event: Payments.PaymentCaptured`) when something
happened. The client is generated from the producer's committed `stackra.manifest.json`; the root
runway's topology decides whether it runs in the same process or over RPC, and the calling code
never changes. You never import another service's code, tables or package.

## Config and where a fact goes

Behaviour is a config class: `class CommerceConfig extends Config` in `src/config/`, its key derived
from the file. A host changes a package's behaviour with a subclass of `override` members:
`class CommerceLoyaltyKitConfig extends LoyaltyKitConfig { override maxRedeemPercent = 30; }`. It is
read through the container, by constructor injection in a binding or `useConfig(Class)` in a React
component, never by importing an instance.

| The fact is                                                | It goes in                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| the same everywhere and read only by build tools           | `stackra.config.ts` (`defineApp`, `defineService`, `definePackage`) |
| read by code while the app runs                            | a config class in `src/config/`                                     |
| different per environment (sizes, values, dedicated needs) | the member's `runway.yaml`                                          |
| where members run and how they are packed                  | the root `runway.yaml` topology                                     |
| derivable from other facts                                 | nowhere: gen writes it                                              |

Gen writes every runtime entry (`.stackra/entry/<target>.ts`, calling `createApp` from
`@stackra/app/<target>`) and every tool config into `.stackra/`, with a gitignored shim at the
member root for a tool that reads only the root. The one code hatch per tool is `vite.extend.ts`,
`expo.extend.ts`, `metro.extend.ts` or `electron.extend.ts`, add-only, with a `Reason:` header.

## Clients and sites

The console (`apps/console`), the mobile app (`apps/mobile`) and the public site (`apps/web`)
consume manifests the same way: gen infers the consumed services from their `#stackra/clients`
imports (nobody writes a `consumes` list; gen records it in the app's manifest) and emits one family
of descriptors in every app. Types come from the descriptor,
`ActionInput<typeof Commerce.actions.CancelOrder>`, never from a hand-written type. Routes are keyed
by their snake_case route key in `#stackra/routes`. The site is restricted to the `public` API area;
a reference to anything else is a gen error. The site's route modules never import server-only code:
the public clients and the server env reach every loader through the Worker's load context, and a
GET for HTML never sets a cookie.

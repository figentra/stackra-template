The first change most people make is a new field. This page walks one through every file it touches,
in order, and shows what gen says when a step is missing. The example adds an optional customer note
to an order in the commerce service's `orders` module.

## 1. The model is the one source

Columns and indexes live on the model; nothing else declares them.

```ts
// services/commerce/src/modules/orders/models/order.model.ts
/** A note the customer leaves at checkout; shown to staff, never to other customers. */
@Nullable @Str({ max: 280 }) note!: string | null;
```

## 2. Generate the migration

```bash
pnpm --filter @acme/service-commerce exec stackra db diff add-order-note
```

`stackra db diff` compares the models with the committed migrations and writes the blueprint step.
Review it, then commit it; committed migrations are never edited again.

```ts
// services/commerce/src/modules/orders/migrations/0003-add-order-note.migration.ts
/**
 * generated by stackra db diff from orders.Order — review, then commit
 * Purpose: adds the nullable `orders.note` column.
 * Boundary: schema only; no data moves.
 * Runtime: node
 */
export class AddOrderNoteMigration extends Migration {
  up(schema: Blueprint) {
    schema.table(Orders, (t) => t.string(Orders.columns.note, 280).nullable());
  }
}
```

`Orders.columns.note` exists because gen regenerated `#stackra/tables` from the model.

## 3. The wire shapes

Input and output are schema classes, one per file. Add the field where the action accepts it and
where the view returns it:

```ts
// orders/schemas/create-order-input.schema.ts — inside the z.object
note: z.string().max(280).optional(),

// orders/schemas/order-view.schema.ts — inside the z.object
note: z.string().optional(),
```

App forms derive from the action input (`Commerce.actions.CreateOrder.input.pick(…)`), so the
console's quick-order form and the mobile create-order sheet see the field after the next `pnpm
gen`, without a second declaration.

## 4. The label

```json
// services/commerce/assets/lang/en/orders.json and ar/orders.json, under "order"
"note": "Customer note"
"note": "ملاحظة العميل"
```

Code references it as `I18n.orders.order.note`; a key present in one locale only fails gen.

## 5. The console column

The column names the model field by key; its label defaults to `orders::order.note`.

```ts
// orders/resources/order.resource.ts
table(t: Table<Order>) {
  // the column names a `keyof Order`, so a typo is a type error
  return t.columns((c) => [/* … */, c.text("note").toggleable()]);
}
```

## 6. The test

```ts
// orders/actions/__tests__/create-order.action.test.ts
/** The note travels from the input to the stored order and back in the view. */
it("stores the customer note", async () => {
  const output = await run(
    CreateOrderAction,
    { ...input, note: "Gift wrap" },
    { as: actors.customer() },
  );
  expect((await run(GetOrderQuery, { orderId: output.orderId })).note).toBe("Gift wrap");
});
```

The contract test (`expectBackwardCompatible`) passes on its own: an optional input field and a new
output field are additive. Making the field required would be a breaking change and needs a dated
`@Change` in `versions/`.

## What gen flags when a step is missing

| You skipped                           | `pnpm gen` / `stackra validate` reports                                              |
| ------------------------------------- | ------------------------------------------------------------------------------------ |
| the migration                         | `orders.Order.note` has no migration; run `stackra db diff`                          |
| a locale of the label                 | `orders::order.note` is missing in `ar`                                              |
| the view field, but a client reads it | the app's `QueryOutput<typeof Commerce.queries.GetOrder>` has no `note` (type error) |
| `pnpm gen` after the schema change    | `stackra gen --check` fails: `.stackra/app-manifest.json` is stale                   |

## The file list

1. `orders/models/order.model.ts`
2. `orders/migrations/0003-add-order-note.migration.ts` (generated, reviewed)
3. `orders/schemas/create-order-input.schema.ts`, `orders/schemas/order-view.schema.ts`
4. `assets/lang/en/orders.json`, `assets/lang/ar/orders.json`
5. `orders/resources/order.resource.ts`
6. `orders/actions/__tests__/create-order.action.test.ts`
7. regenerated, committed: `services/commerce/.stackra/app-manifest.json` and `openapi.json`; the
   apps' clients follow on their next `pnpm gen`

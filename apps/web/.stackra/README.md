# apps/web/.stackra (generated, gitignored; committed in this template only so it can be read)

Written by `stackra gen` in one discovery pass over the member: each file's path gives its kind, its
base class gives its options and its types give its shapes (Stackra ADR 0294). Inputs are
`stackra.config.ts`, `runway.yaml`, `src/config/*.config.ts`, the group folders under `src/`
(`routes/`, `blocks/`, `menus/`, `flags/`, `analytics/`), `assets/` (with the string overrides in
`assets/overrides/`) and the consumed services' committed `stackra.manifest.json` (inferred from
`#stackra/clients` imports). A real project ignores this whole folder and rebuilds it on `pnpm gen`,
on save under `stackra dev`, and before `build`, `test` and `typecheck`. The committed contract is
not here: `stackra.manifest.json` sits at the member root. Every file opens with
`generated by stackra gen from <sources> — do not edit` and is complete. Shorthand: `S` =
stackra.config.ts, `C/<fact>` = src/config/<fact>.config.ts, `RM` = this member's runway.yaml, `RR`
= the root runway.yaml, `K` = the kind classes under `src/`.
